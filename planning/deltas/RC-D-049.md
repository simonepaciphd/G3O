## The rule

Rule sentence. Codebook r18 states it as a new rule of the institution item (`core.has_genai_activity/rules/1`), and the codebook's own convention is that a slot's text is copied from its `source`, which is this delta. > Page-verdict roll-up: a reviewed, unfailed web page whose final verdict is `confirms_activity`, whose verdict support status is `downgraded_quote_not_stating_value` or `downgraded_no_quote`, whose chosen probability passes the classifier verdict bar, and which has at least one supported activity observation on the same page, counts as a supported `confirms_activity` page. `downgraded_low_confidence` is never rescued and a page with no supported activity is never rescued. The verdict is never rewritten and keeps its support status; the source row's `confidence` stays `low`.

**"Web page" is the wording; procurement is not named** (PI 2026-11-22, section 21 item 2). The sentence does not mention procurement pages or AI-text pages. ### Refusals (as on the pre-signature head, `16f6bd5`; `2b5db6f` changes no code)

The PI kept "the two refusals that are stricter than the harness": "a rescue mark on an `unclear` institution; a mark the rule did not make" (section 18). As built:

1. **A mark the rule did not make** (pipeline, `consolidate_v27.py`): a page that carries the mark but is not a page the rule covers is refused (this includes a procurement page and AI-text evidence); a marked page with no supported activity observation is refused.
2. **A rescue mark on an `unclear` institution** (contract model, `g3o/common/contract.py`): a rescued source on an `unclear` institution is refused; `yes` is refused only when every confirming source is downgraded and none is rescued. Stated by the independent review (finding F4) and now by a code comment: no production code sets the contract model's field today, and that model sees no evidence channel, probability or observation, so this half is exercised by its tests only. In production the refusals that act are the pipeline's.
3. **The reverse refusal, added after the independent review** (finding F5; commit `a73a7ca`): a page that meets the rule but arrives without the mark is refused. Before, such a page would have left the institution `unclear` with no error. The per-page producer is the only maker of reviewed pages and sets the mark from the same rule, so no production path is affected (the commit's own statement).

The mark is in memory only. That it is never written out is the integrator's reading of section 16; the review found no write of it ("No leak of the mark") and a test now asserts that no file written for a rolled-up institution names it (commit `9b8ff13`).
