## Changes (proposed)

### A. The codebook is the single source of truth, linked to jev and to the extractor by code (S1)

- D-001 becomes a codebook of record from which the jev question and choice sets (T-011) and the extractor prompts (T-022, T-032) are built programmatically.
- Architecture (ARCH, ruled procedural by the PI, recommendation accepted 2026-10-29, chat "ok as rec"): one machine-readable codebook file in the G3O repo (working name `codebook/codebook.yaml`†) with namespaces `core.*`, `proc.*`, `text.*`. Each item holds its signed wording verbatim; generators only assemble text and never rewrite it, so CX-01.2 stays byte-identical. Generated from it: jev question and choice sets, extractor prompt sections, Python enums and JSON schema, the data dictionary and the human-readable `output_contract.md`. CI fails when a generated file differs from the codebook. The A-001 hash becomes the hash of the codebook file.
- Rollout: v2.7 ships `core.*` and the G3O generators. Procurement moves over at its D-008 step by importing the generated module in place of its `contract.py` copy. The AI-text-detection repo pins a codebook release in place of its vendored `g3o/common/contract.py` (D-009). Neither move blocks v2.7 deployment.
- Default carried with ARCH: the PI signs the wording of every item in every namespace; module owners propose changes.
- New build card (proposed T-013†, lane eng-b): codebook schema, loader and generators, plus the CI check. T-011, T-012, T-022 and T-032 consume its output.
- Every codebook item carries a stable ID, a version, a linkage (jev Choice / deterministic / extractor / pipeline) and its pipeline coverage.
- Affected: D-001, A-001 (adds a linkage check: each generated question or prompt traces to an item ID and hash), T-010 outputs, T-011 (questions generated from the codebook; CX-01.2 stays byte-identical under R-025), T-012 (enum constants possibly generated), T-022 / T-032 (prompts generated), T-031 (reviews the generator as well).
